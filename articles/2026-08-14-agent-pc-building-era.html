    当 Agent 也能「攒机」了

    几个月前搭一套 Agent 还要选框架、写一堆代码。现在一行命令就拿到了。
    📅 2026-08-14 ⏱️ 约 15 分钟 🏷️ AI · Agent · DeepSeek

    那个熟悉的转折，又来了

    我第一次组装电脑是大学时候。

    那时候品牌机性能好、稳定、开箱即用，但贵，而且你没法改里面的东西。后来攒机文化起来了——自己选 CPU、主板、内存、机箱，不一定比品牌机好看，但每一件都是你挑的，跑你自己的活儿特别顺手。

    2026 年 8 月 14 日，我在自己电脑上跑完一行命令：

    npx @deepseek-ai/dsh web

    几秒钟后，浏览器弹出 http://127.0.0.1:3080，一个完整的 Agent 工作台——Web 界面、命令行、插件体系——全有了。

    那个感觉太熟悉了。Agent 的「攒机时代」来了。

    🖥️
    品牌电脑
    性能好、稳定、开箱即用。但贵，而且没什么能自定义的。对应：闭源 Agent（ChatGPT、Claude 等）
    🔧
    自己攒的电脑
    不能说 100% 开箱即用，但根据自己的需求来定制、构建，也能发挥很大的作用。对应：开源 Agent Harness（DeepSeek Harness 等）

    几个月前，搭一套 Agent 是什么体验

    今年上半年，我想给自己搭一套 Agent 工作流。

    流程是这样的：先选框架——LangChain？Dify？n8n？每个都有自己的生态和坑。选完框架开始写代码：定义 Agent 的角色、挂工具、写 prompt 模板、搭 web 界面让非技术同事也能用。光是让一个 Agent 能稳定跑起来，就要写不少前后端代码。

    不是说做不到。做到了，也跑起来了。但那是「从头攒」——选零件、焊电路板、装机箱，全套都来。

    然后 8 月 13 日，DeepSeek 把 Harness 正式发布到 npm（0.1.0-rc.5）。8 月 14 日我就把它拉下来改成了自己的。

    这中间发生了什么？不是模型变了，是基础设施变了。有人把机箱、主板、电源、散热都给你做好了，你只需要选 CPU 和内存。

    几个月前
    • 选框架（LangChain / Dify / n8n）
    • 定义 Agent 角色与工具
    • 写 prompt 模板
    • 搭 web 界面（前后端代码）
    • 调试、部署、维护
    →
    现在
    • npx @deepseek-ai/dsh web
    • Web GUI + CLI + 插件体系
    • 多 provider 模型路由
    • MCP 连接、技能系统
    • 开箱即用，按需定制

    五分钟上手：你的第一台「Agent 攒机」

    方式一：npm 一行拉起（最快）

    装好 Node.js 之后，终端里跑：

    npx @deepseek-ai/dsh web

    就这样。默认打开 http://127.0.0.1:3080，你会看到一个完整的 Web 界面——左边栏是会话列表，中间是对话区，底部是输入框。填上你的 API key（支持多家 provider），就能开始用了。

    这一步对应攒机里的「买整机点亮」——先确认能跑，再谈定制。

    方式二：从源码构建（想深度定制的必经路）

    如果你要改品牌、加能力、做自己的 Agent 预设——得从源码走：

    git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

    跑完 pnpm run build 之后，pnpm dsh web 启动的就是你本地构建的版本。改了源码，重新 build，刷新页面就生效。

    提示：这个项目用 pnpm 管理 monorepo。如果你没装 pnpm，先 npm install -g pnpm。Node.js 版本建议 20+。

    你拿到了什么

    启动之后你拥有的不只是一个聊天界面。DeepSeek Harness 的架构是 「everything is a plugin」——底层由 Cordis 驱动，每一块能力（对话、工具、MCP 连接、技能、主题）都是一个独立的插件包。

    这意味着什么？

    你不喜欢默认主题？换。你想加浏览器截图能力？装个 browser 插件。你想挂一批营销 skills？写个 preset。每一块都能单独替换，不影响其他块。

    这就是攒机的意义：不是所有零件都要自己造，但你保有选择权和替换权。

    开始定制：选你的「CPU 和显卡」

    接下来是我 8 月 14 日实际做的事情。从上游仓库出发，改了 130 多个文件，把一套通用产品改成了自己的 Agent 工作台。下面挑几件最有代表性的讲。

    130+
    修改/新增文件
    22
    内置皮肤
    40
    文生图模型
    54
    营销 Skills

    第一件：换品牌色——给机箱喷漆

    上游的品牌色是 DeepSeek 的蓝色。我要换成自己的品牌色——一种酸性绿 #C8F050。

    听起来就是改几个颜色值？没那么简单。

    这个绿色在白色背景上对比度只有大约 1.5:1，根本不能当前景文字用。而上游有两处地方把品牌色当文字前景用——选中行的图标、徽标上的文字。直接换色，这两处会变成白底上的浅绿文字，几乎看不见。

    解决方法是新增一个语义层 token：--dsw-alias-label-accent。前景用绑这个 token（在浅色主题下解析到更深的 lime-800），填充用绑原来的 info-fill token。

    最终改了多少？11 个静态色值 + 3 个 alias 决策，158 个 alias 条目一个没动。

    这就是好架构的价值：改品牌色不用重写设计系统，因为所有 call site 都绑定在语义 alias 上，而不是直接写死颜色。当然，任何硬编码颜色的地方（比如发送按钮里的 #fff）还是得手动修——没有 gate 能自动抓到这些。

    第二件：皮肤系统——换机箱面板

    上游只有亮色/暗色两个主题。我移植了一个社区项目 HeiGeAi/deepseek-harness-skin 的皮肤系统，带来 22 个内置皮肤。

    这个系统的精妙之处在于四种子色派生：一个皮肤只存四个种子色 + 外观偏好 + chrome 风格，构建时脚本自动派生出完整的调色盘。而且每套皮肤在构建时都要过 WCAG 可读性审计——前景/背景对比度不达标，直接拒绝发布。

    之前有一个 ui-theme-noir 包，35 个手挑 token，没有任何可读性保证。现在同样的黑金外观从四个种子派生出来，构建时自动审计，更安全也更省心。35 个手挑 token 的包直接退役。

    用户还可以用一张照片自定义皮肤——系统从照片里提取种子色，根据照片的明暗极值调透明度 veil，生成一套独属皮肤。这就像当年攒机时贴一张自己喜欢的机箱贴纸——但它会自动调好所有配色。

    第三件：加能力 seam——装显卡和声卡

    DeepSeek Harness 每加一个新能力，都是一个 capability seam，三角色结构：

    Service Definition
    定义 ctx.xxx 接口
    注册表 + 执行时选择
    📐 主板插槽规范
    →
    Provider
    实现接口（可替换）
    Playwright / OpenRouter
    🎮 你插的显卡
    →
    Consumer
    工具层，调用接口
    browser_screenshot 等
    🔧 驱动程序

    我加了两个 seam：

    浏览器 seam（packages/browser/）：上游的网页抓取是纯 HTTP 请求，不执行 JavaScript，SPA 页面返回的是空壳。新 seam 基于 Playwright，能截图、能抓渲染后的页面文本。营销分析（CRO 视觉层级审计、AI-SEO 检测、反爬评论平台）都需要真浏览器。

    图片生成 seam（packages/image/）：通过 OpenRouter 接了 40 个文生图模型。工具返回的是纯文本（附件引用 + 模型信息），不是 inline 图片——因为生成的图不需要模型"看"、只需要"交付"，纯文本结果还能在纯文本路线上继续工作，完全绕开了 assistant 侧图片 block 的 compaction 限制。

    给 harness 加能力的核心原则：新能力做成独立 side seam，不要改现有 seam。图片生成不接在 chat adapter 上（会碰 streaming/compaction/replay），浏览器不接在 web fetch 上（会破坏匿名检索契约）。每个 seam 各管各的生命周期，互不干扰。

    第四件：Agent 预设——装系统的时候选预装软件

    我有一套 pi-agent 的营销 skills 库——54 个 agentskills.io 格式的 skills，覆盖 A/B 测试、广告创意、竞品分析、CRO、AI-SEO 等。

    我不想 fork 整个 host，只想让跑营销任务的 Agent 能用这些 skills。解决方案是写一个 preset（apps/cli/config/agent-presets/marketing/agent.cordis.yml）：

    # 四处关键 delta（示意）：
# 1. skill-filesystem 增 customSkillDirs → 挂载外部 skills 库
# 2. catalogDescriptionMaxLength: 1200 → 不截断 skills 的触发词表
# 3. fetch: true → CRO/AI-SEO skills 需要分析实时 URL
# 4. 挂载 Playwright MCP → 渲染浏览、截图、反爬源

    preset 管 per-agent composition（挂哪些 skills、开哪些 tools、绑哪个 MCP），而 capability seam 管 per-agent 能力的生命周期。两者分工明确：browser subprocess 的成本不该加到 minimal/code preset 上，只有 marketing preset 才挂它。

    攒机哲学：不是所有预设都装一样的软件。游戏机装显卡驱动和游戏，办公机装办公套件。Agent 也是——跑代码的 preset 不需要浏览器，跑营销的 preset 才需要。

    CLI 到 GUI：更多人能用了

    有一件事值得单独说。

    之前我用 pi-agent，纯 CLI。技术人用着顺手，但组织里更多的人——运营、市场、HR——看到终端窗口就头疼。

    DeepSeek Harness 的 Web UI 改变了这件事。http://127.0.0.1:3080 打开就是图形界面，会话管理、工具调用结果、设置面板都在浏览器里。从 CLI 到 GUI，这一步让 Agent 从「只有技术人能用」变成了「组织里更多人能用」。

    这不是技术升级，是受众扩展。攒机文化真正普及，不是从极客圈开始的，是从品牌机用户发现"原来我也能自己选配置"开始的。

    攒完之后，才是真正的赛题

    机器攒好了。品牌色喷好了，22 套皮肤装上了，浏览器和图片生成两个 seam 加上了，54 个营销 skills 挂上了，连自己的 /leo-log 和 /article 工作流都移植过来了。

    坐下来看着这套东西的时候，我突然意识到一件事。

    Agent 能力本身，已经不是壁垒了。

    当 npx 一行就能拉起一个完整的 Agent 工作台——Web GUI、CLI、插件体系、MCP 连接、多 provider 模型路由——「有没有 Agent」这个问题已经没有意义了。人人都有。

    那什么才是壁垒？

    你的私有数据。你的工作上下文。你能不能把这些东西有效地管理和沉淀下来。

    这跟几个月前我写过的一篇文章「无论大模型怎么变，不变的是你个人的"上下文"与 Harness」是一条线上的认识。那篇文章讲的是「追什么模型都是消耗，建上下文和建能力才是积累」。但当时还没想到这一层：当开源 harness 把 Agent 能力的门槛打到底，上下文管理的价值就被进一步放大了。

    打个比方。你攒了一台顶级电脑，CPU 最强、显卡最好、内存拉满。但里面没有你的文件、没有你的项目、没有你的工作流配置——它就是一堆硬件。真正让这台电脑值钱的，是你装在上面的东西。

    Agent 也是。Harness 是硬件，上下文是软件。

    从个人上下文到团队上下文

    这推到了我正在做的一件事：把自己的个人工作上下文系统（leo-brain）升级成一个可供团队协作的 Agent 工作上下文系统。

    leo-brain 是我用 GitLab 同步的个人上下文——我是谁、我的项目地图、我的决策记录、我的工作规则。每个 session 自动加载。它让 Agent 一开口就知道我的背景，不用每次重新喂。

    但它是个人的。

    组织里每个人有自己的 Agent，但共享同一套工作上下文——这件事以前做不到，因为 Agent 本身就是稀缺品，谁先有谁就赢了。现在 Agent 不稀缺了，稀缺的是上下文。当一个组织能把每个人的工作上下文有效沉淀、共享、接续——这个组织的 Agent 协作能力，就不是"有 Agent"能追赶的。

    这不是锦上添花。是踩在新门槛上的必经一步。

    所以，你要不要也攒一台？

    如果你是个人开发者——直接 npx @deepseek-ai/dsh web，五分钟体验。觉得好用，从源码走，开始定制自己的品牌、主题、能力。

    如果你是团队负责人——开源 harness 不只提升个人效率，还能成为组织的统一 Agent 工作台。每人用自己的 Agent，但共享同一套上下文。这才是组织级的 Agent 协作。

    如果你是中小企业——别在 Agent 能力上卷了。开源 harness 已经把这条赛道拉平了。把精力放在你的私有数据和工作上下文的管理上，那才是你的护城河。

    品牌电脑给了你开箱即用，攒机给了你选择权。Agent 也是一样。而选完零件、装好机器之后，真正值钱的，是你装进去的东西。
