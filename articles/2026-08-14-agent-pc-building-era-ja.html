    Agentも「自作PC」を組める時代になった

    数ヶ月前まで、Agentを一つ組むにはフレームワークを選び、大量のコードを書く必要があった。今はコマンド一行で手に入る。
    📅 2026-08-14 ⏱️ 約15分 🏷️ AI・Agent・DeepSeek

    あの見覚えのある転換が、また訪れた

    初めて自分でパソコンを組み立てたのは大学生の頃だった。

    当時のメーカー製パソコンは性能が良く、安定していて、箱を開けてすぐ使える。ただし高価で、中身を自分で変えることはできない。やがて「自作PC文化」が広がった。CPU、マザーボード、メモリ、ケースを自分で選ぶ。見た目はメーカー製ほど洗練されていないかもしれないが、一つひとつを自分で選んでいるからこそ、自分の作業にぴったり合う一台になる。

    2026年8月14日、自分のパソコンで次の一行を実行した。

    npx @deepseek-ai/dsh web

    数秒後、ブラウザに http://127.0.0.1:3080 が開き、完成されたAgentワークベンチが目の前に現れた。Web画面、コマンドライン、プラグイン体系——すべて揃っていた。

    その感覚には既視感があった。Agentの「自作PC時代」がやってきたのだ。

    🖥️
    メーカー製パソコン
    性能が良く安定していて、箱を開けてすぐ使える。ただし高価で、カスタマイズできる余地はほとんどない。対応するのは、クローズドなAgent（ChatGPT、Claudeなど）。
    🔧
    自作パソコン
    100%箱出しですぐ使えるとは言えないが、自分のニーズに合わせてカスタマイズし、組み立てれば大きな力を発揮する。対応するのは、オープンソースのAgent Harness（DeepSeek Harnessなど）。

    数ヶ月前、Agentを一つ組み立てるとはどういうことだったか

    今年上半期、自分用のAgentワークフローを組みたいと思ったことがある。

    手順はこうだった。まずフレームワークを選ぶ——LangChainか、Difyか、n8nか。どれもそれぞれ独自のエコシステムと落とし穴を抱えている。フレームワークを選んだら、今度はコードを書く番だ。Agentの役割を定義し、ツールを接続し、プロンプトテンプレートを書き、技術者でない同僚でも使えるようにWeb画面を作る。Agentを一つ安定して動かすだけでも、かなりの量のフロントエンド・バックエンドコードを書くことになる。

    できないわけではない。実際にできたし、動くようにもなった。だがそれは「ゼロから組む」やり方だった——部品を選び、基板をはんだ付けし、ケースを組む、その全工程を自分でやるということだ。

    そして8月13日、DeepSeekがHarnessをnpmに正式公開した（0.1.0-rc.5）。8月14日には、それを引っ張ってきて自分専用に改造していた。

    この間に何が起きたのか。モデルが変わったわけではない。インフラが変わったのだ。誰かがケース、マザーボード、電源、冷却まで全部用意してくれていて、あとはCPUとメモリを選ぶだけでいい状態になった。

    数ヶ月前
    • フレームワークを選ぶ（LangChain / Dify / n8n）
    • Agentの役割とツールを定義する
    • プロンプトテンプレートを書く
    • Web画面を組む（フロント・バックエンドのコード）
    • デバッグ、デプロイ、保守
    →
    今
    • npx @deepseek-ai/dsh web
    • Web GUI + CLI + プラグイン体系
    • 複数プロバイダーのモデルルーティング
    • MCP接続、スキル体系
    • 箱出しですぐ使え、必要に応じてカスタマイズできる

    5分で始める：あなたの最初の「Agent自作PC」

    方法1：npmで一行起動（最速）

    Node.jsをインストールしたら、ターミナルで次を実行する。

    npx @deepseek-ai/dsh web

    これだけだ。デフォルトで http://127.0.0.1:3080 が開き、完成されたWeb画面が現れる——左サイドバーはセッション一覧、中央が会話エリア、下部が入力欄。APIキー（複数プロバイダー対応）を入力すれば、すぐに使い始められる。

    この一歩は自作PCで言う「完成品を電源につないで動作確認する」段階に当たる。まず動くことを確かめてから、カスタマイズの話に入る。

    方法2：ソースからビルドする（本格的にカスタマイズするなら避けて通れない道）

    ブランドを変えたい、機能を追加したい、自分専用のAgentプリセットを作りたいなら、ソースコードから始める必要がある。

    git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

    pnpm run build を実行し終えたら、pnpm dsh web で起動するのはローカルでビルドした自分のバージョンになる。ソースを変更して再ビルドし、ページを更新すればすぐに反映される。

    ヒント：このプロジェクトはpnpmでmonorepoを管理している。pnpmが入っていなければ、まず npm install -g pnpm を実行しよう。Node.jsは20以上を推奨。

    手に入れたもの

    起動して手に入るのは、単なるチャット画面だけではない。DeepSeek Harnessのアーキテクチャは「everything is a plugin」——すべてがプラグインという思想で作られている。基盤はCordisが駆動していて、対話、ツール、MCP接続、スキル、テーマといった各機能ブロックが、それぞれ独立したプラグインパッケージになっている。

    これは何を意味するのか。

    デフォルトのテーマが気に入らなければ、差し替えればいい。ブラウザのスクリーンショット機能が欲しければ、browserプラグインを入れればいい。マーケティング用のスキル群をまとめて使いたければ、presetを一つ書けばいい。どのブロックも単独で入れ替えられ、他のブロックに影響しない。

    これこそが自作PCの意味だ。すべての部品を自分で作る必要はない。だが選ぶ権利と、入れ替える権利は自分の手に残る。

    カスタマイズを始める：自分の「CPUとグラフィックボード」を選ぶ

    ここからは、8月14日に実際にやったことだ。上流のリポジトリを起点に、130以上のファイルを変更し、汎用プロダクトを自分専用のAgentワークベンチに作り替えた。以下、特に代表的なものをいくつか紹介する。

    変更・追加したファイル数
    22

    その1：ブランドカラーを変える——ケースに塗装する

    上流のブランドカラーはDeepSeekのブルーだった。自分のブランドカラー——蛍光グリーンの #C8F050 に変えたい。

    色の値をいくつか書き換えるだけの話に聞こえるかもしれない。だが、そう単純ではなかった。

    この緑は白背景に対してコントラスト比が約1.5:1しかなく、文字色として使うにはまったく足りない。ところが上流では、選択中の行のアイコンやバッジの文字色にブランドカラーがそのまま使われている箇所が2つあった。そのまま置き換えると、白地に薄緑の文字になり、ほとんど読めなくなってしまう。

    解決策は、意味づけされたトークンを新たに一つ追加することだった。--dsw-alias-label-accent。文字色にはこのトークンを結び付け（ライトテーマではより濃い lime-800 に解決される）、塗りつぶしには元のinfo-fillトークンを結び付ける。

    最終的な変更量は、静的な色値11個 + エイリアスの判断3件。158個あったエイリアスのエントリは一つも触っていない。

    これが良い設計の価値だ。ブランドカラーを変えるのにデザインシステムを書き直す必要がないのは、すべての呼び出し箇所が色の直書きではなく、意味づけされたエイリアスに紐づいているからだ。もちろん、送信ボタンの #fff のようにハードコードされた色は手で直す必要がある——これを自動で検知してくれる仕組みは存在しない。

    その2：スキン体系——ケースのパネルを取り替える

    上流にはライト/ダークの2テーマしかなかった。コミュニティプロジェクトのHeiGeAi/deepseek-harness-skinのスキン体系を移植し、22種類の内蔵スキンを追加した。

    この仕組みの巧みなところは4つのシード色からの派生にある。一つのスキンが保持するのは、4つのシード色と外観の好み、chromeのスタイルだけで、ビルド時にスクリプトが自動で完全な配色パレットを導き出す。しかも各スキンはビルド時にWCAGの可読性監査を必ず通過しなければならない——前景色と背景色のコントラストが基準に満たなければ、そのまま公開が拒否される。

    以前は ui-theme-noir というパッケージがあり、35個のトークンを手作業で選んでいたが、可読性の保証は一切なかった。今では同じ黒と金の外観が4つのシードから派生し、ビルド時に自動監査される。より安全で、手間もかからない。手作業で選んでいた35個のトークンのパッケージは、そのまま役目を終えた。

    ユーザーは一枚の写真から自分専用のスキンを作ることもできる——システムが写真からシード色を抽出し、写真の明暗の振れ幅に応じて透明度（veil）を調整し、その人だけのスキンを一つ生成する。これは自作PC時代に自分の好きなステッカーをケースに貼るのに似ている。ただし、こちらは配色まで全部自動で調整してくれる。

    その3：機能のseamを追加する——グラフィックボードとサウンドカードを増設する

    DeepSeek Harnessでは、新しい機能を追加するたびにcapability seamという、3つの役割からなる構造を作ることになる。

    Service Definition
    ctx.xxx インターフェースを定義
    レジストリ＋実行時の選択
    📐 マザーボードのスロット規格
    →
    Provider
    インターフェースの実装（差し替え可能）
    Playwright / OpenRouter
    🎮 実際に挿すグラフィックボード
    →
    Consumer
    ツール層、インターフェースを呼び出す
    browser_screenshot など
    🔧 ドライバソフト

    今回、2つのseamを追加した。

    ブラウザseam（packages/browser/）：上流のWebページ取得は純粋なHTTPリクエストで、JavaScriptを実行しないため、SPAページからは空っぽの中身しか返ってこない。新しいseamはPlaywrightをベースにしていて、スクリーンショットが撮れ、レンダリング後のページテキストも取得できる。マーケティング分析（CROの視覚的階層監査、AI-SEOのチェック、クローラー対策済みの口コミサイトの解析など）には、実際に描画するブラウザが欠かせない。

    画像生成seam（packages/image/）：OpenRouter経由で40種類の画像生成モデルに接続した。ツールが返すのは純粋なテキスト（添付ファイルの参照＋モデル情報）で、画像をそのまま埋め込みはしない。生成した画像はモデルが「見る」必要はなく、「届ける」だけでよいからだ。テキストのみの結果にしておけば、テキストベースの処理経路の中で問題なく動き続けられ、assistant側の画像ブロックにまつわるcompaction制限を完全に回避できる。

    harnessに機能を追加する際の基本原則は、新しい機能は独立したside seamとして作り、既存のseamには手を入れないこと。画像生成をchat adapterに接続しないのは、streaming・compaction・replayに影響が及ぶからだ。ブラウザをweb fetchに接続しないのは、匿名での取得契約を壊してしまうからだ。それぞれのseamが自分のライフサイクルだけを管理し、互いに干渉しない。

    その4：Agentプリセット——OSを入れるときにプリインストールソフトを選ぶ

    手元にはpi-agent用のマーケティングスキルライブラリがある——A/Bテスト、広告クリエイティブ、競合分析、CRO、AI-SEOなどをカバーする、agentskills.io形式のスキルが54個。

    host全体をforkしたいわけではなく、マーケティング業務を担当するAgentだけがこれらのスキルを使えるようにしたい。そこでpresetを一つ書いた（apps/cli/config/agent-presets/marketing/agent.cordis.yml）。

    # 主な変更点4つ（要約）：
# 1. skill-filesystemにcustomSkillDirsを追加 → 外部のスキルライブラリをマウント
# 2. catalogDescriptionMaxLength: 1200 → スキルのトリガー語一覧を切り詰めない
# 3. fetch: true → CRO/AI-SEOスキルはリアルタイムのURL分析が必要
# 4. Playwright MCPをマウント → 描画ブラウジング、スクリーンショット、クローラー対策サイトの取得

    presetはagentごとの構成（どのスキルを付けるか、どのツールを開放するか、どのMCPを結び付けるか）を管理し、capability seamはagentごとの機能のライフサイクルを管理する。両者の役割分担ははっきりしていて、ブラウザのサブプロセスにかかるコストは minimal や code のpresetには乗せず、marketing presetにだけ載せる。

    自作PCの流儀：どのプリセットにも同じソフトを入れるわけではない。ゲーム機にはグラフィックドライバとゲームを入れ、事務用マシンにはオフィスソフトを入れる。Agentも同じだ。コードを書くためのpresetにブラウザは要らないが、マーケティング用のpresetには必要になる。

    CLIからGUIへ：使える人が増えた

    これは一つ、あえて独立して触れておきたい話だ。

    これまでpi-agentを使っていた頃は、純粋なCLIだった。技術者は問題なく使いこなせるが、組織にはもっと多くの人がいる——運営、マーケティング、人事といった人たちは、ターミナル画面を見た瞬間に手を止めてしまう。

    DeepSeek HarnessのWeb UIは、この状況を変えた。http://127.0.0.1:3080を開けば、そこにはグラフィカルな画面が広がっている。セッション管理、ツール呼び出しの結果、設定パネル、すべてがブラウザの中で完結する。CLIからGUIへ——この一歩によって、Agentは「技術者だけが使えるもの」から「組織のより多くの人が使えるもの」へと変わった。

    これは技術的なアップグレードではなく、利用者層の拡大だ。自作PC文化が本当の意味で広まったのも、ギーク層からではなく、メーカー製パソコンのユーザーが「自分でも構成を選べるんだ」と気づいたところから始まっている。

    組み上がった後こそ、本当の勝負が始まる

    マシンは組み上がった。ブランドカラーは塗り直し、22種類のスキンを装備し、ブラウザと画像生成という2つのseamを増設し、54個のマーケティングスキルを取り付け、自分の /leo-log や /article といったワークフローまで移植し終えた。

    座ってこの一式を眺めていたとき、あることにふと気づいた。

    Agentの能力そのものは、もはや参入障壁ではなくなった。

    npxを一行実行するだけで、Web GUI、CLI、プラグイン体系、MCP接続、複数プロバイダーのモデルルーティングを備えた完成されたAgentワークベンチが立ち上がる。もはや「Agentを持っているかどうか」という問いには意味がない。誰もが持っている。

    では、何が本当の参入障壁になるのか。

    それは自分だけが持つデータであり、自分の仕事の文脈（コンテキスト）であり、それらを実際にどれだけうまく管理し、積み上げていけるかということだ。

    これは数ヶ月前に書いた「モデルがどう変わろうと、変わらないのは個人の『コンテキスト』とHarnessである」という記事と同じ線上にある気づきだ。あの記事で書いたのは、「どのモデルを追いかけても消耗するだけで、コンテキストと能力を積み上げることこそが資産になる」ということだった。だが当時はまだ、ここまでは考えが及んでいなかった。オープンソースのharnessがAgentの能力の敷居を底まで下げたとき、コンテキスト管理の価値はさらに大きく増幅されるということだ。

    例え話をしよう。最高スペックのパソコンを一台組んだとする。CPUは最強、グラフィックボードも最高、メモリも目一杯積んだ。だが、その中に自分のファイルも、自分のプロジェクトも、自分の作業フローの設定も入っていなければ、それはただのハードウェアの塊にすぎない。そのパソコンを本当に価値あるものにするのは、その上に積み上げたものだ。

    Agentも同じだ。Harnessはハードウェアであり、コンテキストはソフトウェアである。

    個人のコンテキストから、チームのコンテキストへ

    この気づきは、いま自分が取り組んでいることにつながっている。個人用の仕事コンテキストシステム（leo-brain）を、チームで協働できるAgent向けの仕事コンテキストシステムへと発展させる、という取り組みだ。

    leo-brainは、GitLabで同期している自分専用のコンテキストだ。自分が何者か、自分のプロジェクトの地図、自分の意思決定の記録、自分の仕事のルール——これらをセッションのたびに自動で読み込む。おかげでAgentは話し始めた瞬間から自分の背景を理解していて、毎回イチから説明し直す必要がない。

    だが、これはあくまで個人のものだ。

    組織の中で一人ひとりが自分のAgentを持ちながら、同じ一つの仕事コンテキストを共有する——これは以前は実現できなかった。なぜならAgent自体が希少な資源で、先に手に入れた者が勝つ状況だったからだ。だが今やAgentは希少ではなくなり、希少なのはコンテキストのほうになった。組織が一人ひとりの仕事コンテキストを効果的に蓄積し、共有し、引き継いでいけるかどうか——それこそが、単に「Agentを持っている」だけでは追いつけない、その組織のAgent協働能力の差になる。

    これはあれば嬉しいという程度の話ではない。新しい敷居の上に立つための、避けて通れない一歩だ。

    では、あなたも一台組んでみないか

    もし個人開発者であれば——まずは npx @deepseek-ai/dsh web を実行して、5分だけ体験してみてほしい。良いと感じたら、ソースコードから始めて、自分のブランド、テーマ、機能のカスタマイズに進めばいい。

    もしチームの責任者であれば——オープンソースのharnessは個人の生産性を高めるだけでなく、組織全体で統一して使えるAgentワークベンチにもなり得る。一人ひとりが自分のAgentを使いながら、同じコンテキストを共有する。それこそが組織レベルのAgent協働だ。

    もし中小企業であれば——Agentの能力そのものを競うのはもうやめたほうがいい。オープンソースのharnessが、この土俵をすでに平らにしてしまった。力を注ぐべきは、自社だけが持つデータと仕事のコンテキストをどう管理するかであり、そここそが本当の意味での競争優位になる。

    メーカー製パソコンは箱出しですぐ使える手軽さをくれた。自作PCは選ぶ自由をくれた。Agentも同じだ。そして部品を選び、マシンを組み上げた後に本当に価値を持つのは、その中に積み上げたものである。
